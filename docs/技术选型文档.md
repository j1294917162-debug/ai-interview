# 技术选型文档

## 概述

本文档记录了项目各技术环节的选型方案及决策理由。

---

## AI 模型

| 项目 | 选型 | 理由 |
|------|------|------|
| 模型 | **GLM-4-Flash** (`glm-4-flash`) | 1. 分析速度快、成本低，适合批量筛选场景<br>2. 中文原生支持：智谱模型在中文理解和生成方面表现优秀<br>3. 结构化输出稳定：遵循 JSON 格式要求<br>4. OpenAI 兼容接口：标准 Chat Completions API，接入简单 |
| 温度参数 | `0.3` | 低温度保证分析结果的一致性和稳定性，适合标准化评估场景 |
| 最大输出 | `1024 tokens` | 足够容纳完整 JSON 报告（含中文），避免截断 |
| 备选模型 | `glm-4` / `glm-4-plus` | 如需要更高分析质量可切换，但成本会相应增加 |

---

## 前端方案

| 项目 | 选型 | 理由 |
|------|------|------|
| 技术栈 | **纯 HTML/CSS/JS**（单文件） | 1. 零构建步骤：无需 webpack/vite 等构建工具<br>2. 零外部依赖：无 npm 依赖，无 CDN 引用<br>3. 易于维护：非技术人员可用记事本查看代码<br>4. 加载极快：本地文件，无网络请求 |
| 框架 | **不使用任何框架** | 项目规模小（单页面、少量交互），引入框架反而增加复杂度 |
| 布局 | **CSS Flexbox + Grid** | 现代浏览器 100% 支持，无需 polyfill |

---

## 后端方案

| 项目 | 选型 | 理由 |
|------|------|------|
| 运行时 | **Node.js 内置 `http` 模块** | 1. 零 npm 依赖：不需要 `npm install`<br>2. 用户已安装 Node.js v24.16.0<br>3. v24 内置全局 `fetch` API，直接调用 Anthropic API |
| 框架 | **不使用 Express 等框架** | 仅需处理 2 个路由（GET `/`、POST `/api/analyze`），内置模块足够 |
| 端口 | **3000** | 标准开发端口，一般不会冲突 |

---

## 部署方案

| 项目 | 选型 | 理由 |
|------|------|------|
| 方式 | **本地 localhost** | 1. 数据安全：候选人数据不离开本地<br>2. 零服务器成本：无需购买云服务<br>3. API Key 安全：Key 在本地内存中，不暴露到公网 |
| 启动方式 | **start.bat 一键启动** | Windows 批处理脚本，双击即可，无需打开命令行 |
| 编码 | **UTF-8** | 全项目统一 UTF-8 编码，保证中文正常显示 |

---

## 决策总结

本项目的核心选型原则：**极简、零依赖、本地运行**。四个文件即可提供完整的 AI 辅助面试分析能力，没有任何第三方依赖链。
